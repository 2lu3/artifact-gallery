# Artifact Gallery Implementation Plan

Generated by `/plan-eng-review` on 2026-08-31  
Branch: `main`  
Source: `docs/designs/artifact-gallery.md`

## Outcome

Build v1 as a single local Node.js LTS and TypeScript application. React and Vite provide the gallery UI, Fastify exposes a token-protected loopback API, `better-sqlite3` stores catalog and job state, and Playwright renders untrusted HTML with default-deny request routing. Keep all approved v1 recovery behavior; do not split the product into services.

## What already exists

- `docs/designs/artifact-gallery.md` defines the approved product scope, lifecycle, security boundary, success criteria, and distribution constraint. Reuse it as the product source of truth.
- `docs/designs/artifact-gallery-wireframe.png` defines the approved Pinterest-style layout. Reuse it instead of redesigning the UI.
- No application code, package manifest, database schema, test framework, or CI workflow exists yet. There are no existing flows to wrap or reuse.

## NOT in scope

- Semantic search: defer until the v1 lexical-search evaluation identifies real misses.
- File watching and automatic refresh: defer until manual refresh causes measured friction.
- Hash-based relink suggestions: defer until missing references are common enough to justify allowed-root scans.
- Script-enabled HTML: defer to a separate threat model and OS-level isolation design.
- Desktop packaging: intentionally excluded; the product remains a repository-run local web app.
- Multi-user auth, sync, sharing, automatic collection, script execution, and package distribution remain outside v1.

## Technology

- Runtime: current Node.js LTS, TypeScript, pnpm.
- UI: React, Vite, CSS masonry with a deterministic fallback, TanStack Query only if server-state needs justify it.
- API: Fastify bound explicitly to `127.0.0.1`, with a fresh startup session token required by every API request.
- Database: `better-sqlite3`, migrations in SQL, WAL mode, foreign keys enabled, one application writer.
- Rendering: Playwright Chromium, one browser process, at most two disposable contexts.
- Markdown: a CommonMark-compatible parser configured with raw HTML disabled and an explicit element allowlist.
- Tests: Vitest for unit and integration tests; Playwright Test for browser and end-to-end tests.

Keep these as modules in one process, not separately deployed services. The only child process is Chromium managed by Playwright.

## Data model

Use independent facts rather than one overloaded artifact status.

```text
artifact
  id, source_path, format, derived_title, user_title
  source_status: available | missing
  created_at, updated_at, registered_at
  active_generation_id, generation_counter

artifact_generation
  id, artifact_id, generation
  job_status: queued | processing | idle | interrupted
  content_status: pending | ready | failed
  render_status: pending | ready | failed
  index_status: pending | ready | failed
  extracted_text, extractor_version
  thumbnail_path, previewed_at
  started_at, completed_at

artifact_error
  id, artifact_id, generation_id
  code, stage, retryable, user_message, technical_detail, occurred_at

artifact_warning
  id, artifact_id, generation_id, code, detail, occurred_at

allowed_root
  id, canonical_path, created_at

import_run
  id, status, cancel_requested_at, started_at, completed_at

import_item
  id, run_id, canonical_path, artifact_id
  stage, status, error_id, started_at, completed_at
```

Derive card presentation as follows:

```text
source_status == missing                         → missing
job_status in {queued, processing}               → processing
content=ready and render=ready and index=ready   → ready
at least one derived result is ready             → partial
otherwise                                        → failed
```

`missing` changes presentation but never deletes the last successful generation. Partial retry may commit only when its input generation still matches the artifact generation counter.

## Filesystem boundary

Implement one `PathPolicy` and route every filesystem action through it:

- Canonicalize existing paths with `realpath` before containment checks.
- Compare path components, never string prefixes.
- Reject hidden entries, symlinks, traversal, unsupported extensions, directories where files are required, and files where directories are required.
- Enumerate folders recursively without following symlinks and continue after unreadable-item errors.
- Recheck canonical containment immediately before every read to reduce check/use races.
- Treat missing paths as a separate validation method because `realpath` cannot resolve them.
- Use the same policy for import, relink, Finder actions, and Playwright asset fulfillment.

## HTML isolation

Do not create an HTTP asset proxy.

```text
untrusted HTML request
        │
        ▼
Playwright BrowserContext route handler
        ├── http / https / ws / wss            → abort
        ├── loopback and API origin             → abort
        ├── file URL                            → abort
        ├── traversal / symlink / outside root  → abort
        └── canonical allowed local asset       → route.fulfill(bytes, MIME)
```

- Create a fresh browser context per render with JavaScript disabled and `serviceWorkers: "block"`.
- Register the default-deny route before loading any content.
- Load the main HTML from memory, not a `file:` or loopback URL.
- Apply a restrictive CSP to rendered content and block popups, downloads, dialogs, permissions, WebSockets, and external navigation.
- Limit HTML to 10MB, each asset to 10MB, total asset reads to 50MB, and one processing attempt to 30 seconds.
- Reuse one Chromium process with no more than two active contexts. Close every context in `finally`.

## Processing and recovery

All entry points call the same staged `ArtifactProcessor`.

```text
register / refresh / retry / rebuild
                 │
                 ▼
inspect → extract → render → index → commit
   │         │         │        │       │
   └─────────┴─────────┴────────┴───────┴── structured result per stage
```

- Persist an `import_item` transition before starting each stage.
- Write derived files to a temporary path in the same directory as the final file.
- Commit a new generation in SQLite, atomically rename the thumbnail, then retire the old thumbnail. On failure, preserve the previous successful generation.
- A cancel request prevents new stages from starting. A running non-interruptible operation finishes or reaches its timeout, then records cancellation.
- At startup, mark runs and items left in active states as interrupted. Preserve complete derivatives, remove temporary files, and report unstarted items without silently resuming them.
- Upsert by canonical absolute path. A unique database constraint is the final defense against double-click and concurrent imports.

## Thumbnail policy

- WebP, 1200px width, maximum 2400px height, 500KB target.
- Keep only the current successful preview plus a temporary replacement during update.
- Never remove the old preview before the new file and database generation commit succeed.
- Record a warning when a long page is clipped; the lightbox may re-render the source under the same isolation rules.

## Search

- Normalize indexed text and queries with Unicode NFKC and ASCII lowercasing.
- Use SQLite FTS5 trigram for queries of at least three Unicode characters.
- For normalized one- or two-character queries, scan normalized title and content for at most 100 artifacts.
- Apply AND semantics to whitespace-separated terms and phrase semantics to quoted text.
- Index path segments separately and weight user title, derived title, body, and path in that order.
- Compare FTS5 trigram against a prototype bigram implementation on the fixed corpus. Adopt custom bigrams only if FTS5 fails either 18/20 top-five recall or the 200ms latency target.

## API and UI

- Return structured errors with `code`, `stage`, `retryable`, and a safe user message. Keep technical details out of normal UI responses.
- Paginate gallery and search results with stable cursors in pages of 30. Cursor inputs include sort mode and query fingerprint so stale cursors fail explicitly.
- Lazy-load thumbnails and cancel obsolete searches with `AbortController`.
- Measure initial-list SLO from navigation start until the first 30 cards are interactive; measure search from debounced input acceptance until matching cards render.
- Preserve query, filters, sort, scroll anchor, and focused card while the lightbox is open. Restore all state on close.
- Require explicit confirmation before deleting a gallery record. The deletion path must never call a source-file removal API.

## Structured errors

Define a closed initial error taxonomy and an `UNKNOWN` fallback:

- Path: `SOURCE_MISSING`, `OUTSIDE_ALLOWED_ROOT`, `SYMLINK_REJECTED`, `UNSUPPORTED_FORMAT`, `UNREADABLE_SOURCE`.
- Processing: `CANCELLED`, `INTERRUPTED`, `STALE_GENERATION`, `TIMEOUT`, `INPUT_TOO_LARGE`.
- Extraction/rendering: `MARKDOWN_PARSE_FAILED`, `HTML_RENDER_FAILED`, `ASSET_BLOCKED`, `ASSET_TOO_LARGE`.
- Storage/search: `DERIVED_WRITE_FAILED`, `DATABASE_BUSY`, `INDEX_UPDATE_FAILED`, `CURSOR_STALE`.

Map library exceptions at module boundaries. Unknown failures are non-retryable by default until classified.

## Failure modes

| Codepath | Realistic failure | Test | Handling | User experience |
|---|---|---|---|---|
| File/folder registration | unreadable item or duplicate path | integration + E2E | item error; DB unique upsert | completed items remain; failed item named |
| Path authorization | traversal, symlink, path replaced before read | unit + integration | recheck and reject | safe actionable error |
| Markdown extraction | malformed or oversized input | unit + integration | retain artifact and error | retry or remove record |
| HTML rendering | external request, timeout, Chromium crash | real-browser integration | abort, timeout, recreate browser | last preview retained; retry offered |
| Thumbnail replacement | encode or rename failure | integration | temporary cleanup; keep old generation | warning/error without blank card |
| Index update | transaction failure or stale generation | integration | rollback whole generation | previous search result remains |
| Cancellation | cancel during a running stage | integration + E2E | finish/timeout current stage; stop next | explicit cancelled summary |
| Process crash | active item left in SQLite | child-process integration | startup marks interrupted | completed work retained; no spinner forever |
| Search | punctuation, short query, stale cursor | unit + eval + E2E | escaped query; fallback scan; reset page | clear results or no-results state |
| Relink | wrong format or duplicate target | integration + E2E | reject before generation change | missing card preserved |
| Catalog deletion | user double-submits | integration + E2E | idempotent record/derived delete | source file untouched |

No planned failure mode is allowed to have no test, no handling, and silent UI behavior.

Coverage target: 100% of planned branches and all 17 identified user flows. Security, data deletion, crash recovery, and the primary registration journey require integration or E2E coverage; mocks alone are insufficient.

## Performance verification

- Fixed corpus: 50 HTML + 50 Markdown files, at most 50MB source data.
- Cold-start the app for five first-page measurements; require median at or below 1 second.
- Run each fixed search query ten times against a built index; require median render update at or below 200ms.
- Record maxima. Investigate any maximum greater than twice the target.
- Record Chromium peak RSS while processing two contexts and verify cancellation remains responsive.
- Benchmark with thumbnail cache empty and warm as separate cases.

## Distribution and operations

- `pnpm dev` starts API, worker, and Vite UI with one command.
- `pnpm build` produces the web bundle and server output; `pnpm start` runs the production build locally.
- README documents Node/pnpm requirements, Playwright Chromium installation, data locations, allowed roots, startup token behavior, and complete removal.
- CI runs formatting, lint, typecheck, unit/integration tests, Chromium isolation tests, search evaluation, performance smoke thresholds, and production build.
- Pin Node and pnpm versions. Cache Playwright browsers by exact package version.

| Path and error boundaries | `src/server/security/`, `src/shared/` | Foundation |
| Markdown and HTML rendering | `src/server/rendering/` | Path and error boundaries |
| Processing and recovery | `src/server/processing/`, repositories | Foundation, rendering |
| Search | `src/server/search/`, repositories | Foundation |
| API | `src/server/api/` | Processing, search |
| Gallery UI | `src/client/` | Shared contracts; API mocks initially |
| E2E and performance | `tests/`, fixtures, CI | API and UI |

- Lane A: Foundation → Path/error boundaries → Rendering → Processing.
- Lane B: Foundation → Search.
- Lane C: Shared contracts → Gallery UI with mocked API.
- After A + B + C merge: API integration → E2E/security/performance verification.
- Conflict flags: Lanes A and B both touch database migrations and repositories; assign schema ownership to Lane A and have Lane B consume the merged migration. Lane C must not modify server contracts independently.
